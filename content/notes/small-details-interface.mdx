# The small details that make an interface feel finished.

A page can have the right layout, the right colours and all the expected interactions and still feel unfinished.

Usually, the missing part is not another feature. It is the collection of small decisions around the interface: how close a label sits to its value, what happens between hover and click, how a heading breaks at a narrower width, or whether an empty state looks intentional.

## Start with rhythm

I tend to notice spacing before I notice almost anything else. A consistent rhythm gives a page a quiet structure even when the user never consciously sees the grid.

That does not mean every gap needs to be identical. Related things should feel related; unrelated things should have enough separation to become distinct.

## States are part of the design

A button is not just its resting state. Links, inputs, menus, cards and navigation all have moments between states.

At minimum, think through:

- default
- hover
- focus
- active
- disabled
- loading
- error or empty

A useful interface makes those states feel like parts of the same system rather than afterthoughts added at the end.

## Motion should explain something

A transition earns its place when it helps the user understand a change. It can show where something came from, what opened, or what became active.

If removing an animation makes the interface harder to understand, it was probably doing useful work. If nothing changes except that the page looks more impressive, I usually question it.

## The last ten percent

The final polish is rarely one dramatic effect. It is checking the details repeatedly at real viewport sizes, fixing awkward line breaks, tightening alignment, and making sure the interface still feels deliberate when JavaScript or motion is unavailable.

That is the part of frontend work I enjoy most: turning something that technically works into something that feels considered.
